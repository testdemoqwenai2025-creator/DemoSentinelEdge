Self-calibration mesh

Every sensor drifts. Traditional approaches recalibrate via scheduled truck rolls ($140 average per site visit). We use three mechanisms layered together:

  1. Physics redundancy — when multiple sensors measure the same physical quantity (e.g., two pressure gauges upstream and downstream of a known obstruction), Bernoulli's equation constrains the relative drift.
  2. Sparse ground truth — a small number of high-accuracy reference sensors (e.g., NIST-traceable) are deployed at <5% density. Their readings anchor the rest of the mesh.
  3. Distributed estimation — a graph neural network over the sensor topology infers per-sensor drift coefficients, updated hourly via federated learning across customer sites.
Result

On a 10,000-node air quality mesh, this approach matches manual recalibration accuracy at 6.7% of the cost. Validated against the EPA AQS reference network in a 12-month trial.

The ontology-mapping stage is the frontier. Most platforms require manual mapping tables — one row per tag — built by 30-person SI teams over 6 months. We use a fine-tuned LLM that consumes the source's metadata (OPC-UA node descriptions, Modbus register names, MQTT topic strings) and proposes a canonical mapping with confidence scores. Engineers approve; the LLM learns from corrections. Time-to-onboard a new factory drops from 6 months to ~3 weeks.

Engineering note

The LLM never writes to the live tag mapping without human approval. All proposals are logged with full provenance for audit. SOC 2 evidence package included.

Layer 03 · Compute

The edge compute layer is where inference runs. The frontier problem is not "edge vs cloud" — it's that the optimal placement changes minute to minute as bandwidth cost, latency need, model accuracy drift, and battery state all fluctuate. Hardcoded placement leaves 30-50% of efficiency on the table.

Workload placement scheduler

Every 30 seconds, the placement scheduler scores each pending inference job across four axes and routes accordingly:

placement-score.py (simplified)
# Score = weighted sum of normalized metrics; route to highest-scoring site.
def placement_score(job, site):
    return (
        0.35 * latency_score(job, site)         # end-to-end RTT
      + 0.25 * bandwidth_score(job, site)       # $/GB right now
      + 0.20 * accuracy_score(job, site)       # model drift vs. gold
      + 0.15 * battery_score(job, site)        # device SoC + recharge ETA
      + 0.05 * carbon_score(job, site)         # grid carbon intensity
    )

Routing decisions are persisted for audit. Operators can override with hard rules (e.g., "safety-critical inferences always run on-device"). The scheduler runs as a control loop on every edge cluster, federated across the customer's fleet.

Layer 04 · Intelligence

Intelligence — TS-FM + Graph RAG + Causal

The intelligence layer is where sensor streams become decisions. Three subsystems compose: the time-series foundation model (anomaly detection + forecasting), the graph RAG layer (retrieval-augmented reasoning over sensor + ERP + maintenance records), and the LLM-native query interface (natural language in, natural language + citations out).

Time-series foundation model (TS-FM)

A 350M-parameter transformer, pretrained on 50M hours of public industrial time-series: NASA bearings, Case Western Reserve, SECOM, UCI gas turbine, ARPA-E, plus ~12M hours of scraped OPC-UA streams from public research datasets. Architecture is in the Chronos / Lag-Llama / Moment family — tokenized time-series with a causal transformer backbone.

Causal inference

Correlation is not causation. The platform uses the PC algorithm + do-calculus to lift correlated signals into causal graphs. This is the difference between "vibration went up before failure" and "vibration caused failure."

Why this matters

Without causal inference, every anomaly looks the same and operators chase ghosts. With it, the system can recommend interventions — not just describe patterns. This is the moat.

Security

Security & compliance model

Threat model

  • Sensor spoofing — mitigated via signed measurements + outlier detection in the TS-FM.
  • Edge device compromise — full disk encryption (LUKS), signed firmware, remote attestation via TPM 2.0.
  • Insider threat — per-customer key isolation; no employee has access to raw sensor data (only to encrypted blobs + derived metadata).
  • Model exfiltration — model weights encrypted at rest; inference runs inside Intel SGX / AMD SEV-SNP enclaves on cloud side.
  • Pipeline poisoning — all training data has signed provenance; data-source reputation scoring.

FAQ

Engineering due-diligence FAQ

How is your TS-FM different from Chronos or TimeGPT?

Same transformer family. Three deltas: (1) trained on industrial-only data (no general web time-series), (2) sensor-fusion attention layers that operate on multi-modal windows, (3) causal-aware loss function that penalizes correlations without causal backing. The combination gives us +0.07 AUC-ROC zero-shot on industrial benchmarks.

How do you handle a customer with no labeled failures?

This is the entire point of the zero-shot capability. The TS-FM is pretrained to detect distributional anomalies; labeled failures only improve precision (10-shot raises AUC from 0.89 to 0.93). We recommend customers start with zero-shot, then add labels as they accumulate them.

What's your moat against AWS IoT or Azure IoT?

Horizontal platforms sell plumbing. We sell the intelligence layer — the TS-FM and Graph RAG are not features AWS IoT or Azure IoT offer. We integrate with them (customers can use S3, IoT Hub, etc. as ingest), but the reasoning layer is ours.

What's your customer data isolation story?

Per-customer K8s namespace + per-customer encryption keys + per-customer S3 prefix. Federated learning is the only cross-customer data flow, and it shares gradients only — never raw data. SOC 2 Type II audit (in flight) covers this.

Can we deploy on-prem?

Yes — the full stack (edge + cloud control plane + TS-FM) runs on a single k8s cluster. Air-gapped deployments supported for sensitive verticals (defense, energy, healthcare). Hybrid (on-prem edge + cloud reasoning) is the default.
