Four layers. One substrate.

AISensorEdgeComp is not another cloud IoT platform. It is a vertically-integrated four-layer substrate that any sensor, any protocol, any vertical can plug into — and any operator can query in natural language.

Layer 01

Sensing — the physical interface

We do not manufacture sensors — we ingest from any. The value is the sensor ontology that normalizes heterogeneous physical signals into a unified semantic model, plus the self-calibration mesh that keeps them trustworthy over time.

The frontier here is the ontology itself: turning "this float at offset 0x42 in Modbus register 40001" into "compressor outlet pressure in Pa, sampled at 1 Hz, ±120 Pa uncertainty, calibration age 42 days" — automatically, without a 30-person SI team.

Layer 02

Connectivity — protocol-agnostic bridge

A real factory floor runs Modbus, OPC-UA, Profinet, EtherCAT, MQTT, CoAP and proprietary serial — frequently all at once. The connectivity layer ingests from any of these, normalizes to the canonical measurement schema, and transports over any WAN (LoRaWAN, NB-IoT, 5G mMTC, Wi-Fi HaLow, TSN, direct-to-satellite).

The frontier is LLM-assisted semantic normalization. A fine-tuned LLM consumes OPC-UA node descriptions, Modbus register names, MQTT topic strings — and proposes canonical mappings with confidence scores. Engineers approve. Time-to-onboard a new factory drops from 6 months to ~3 weeks.

Layer 03

Edge compute — liquid workload placement

The frontier problem is not "edge vs cloud" — it's that the optimal placement changes minute to minute as bandwidth cost, latency need, model accuracy drift, and battery state all fluctuate. Hardcoded placement leaves 30-50% of efficiency on the table.

Our scheduler runs every 30 seconds, scoring each pending inference job across five axes (latency, bandwidth, accuracy drift, battery, carbon) and routes accordingly. Reduces inference cost by 63% vs. hardcoded cloud-only placement. Lowers p99 latency by 4×.

Layer 04

Intelligence — TS-FM + Graph RAG + causal

Three subsystems compose: the time-series foundation model (anomaly detection + forecasting, 350M params, 50M hours pretrain), the graph RAG layer (retrieval-augmented reasoning over sensor + ERP + maintenance records), and the LLM-native query interface (natural language in, natural language + citations out).

The fourth subsystem is causal inference (PC algorithm + do-calculus). It's what lifts the platform from "descriptive" to "prescriptive" — the difference between "vibration went up before failure" and "vibration caused failure."

Design principles

What we will not compromise on

1. Any sensor, any protocol, any vertical

The substrate is agnostic. We do not play favorites with sensor vendors, network carriers, cloud providers, or vertical SIs. If a customer has invested in a stack, we sit above it — not against it.

2. Edge autonomy is non-negotiable

Every edge cluster runs for 72 hours without WAN. If your plant loses internet, your TS-FM still flags anomalies, your operator still gets alerts, your maintenance log still records. The cloud is a co-processor, not a dependency.

3. Provenance over performance

Every AI output carries a citation chain. "Vibration caused failure" must point at the exact sensor readings and the exact causal test that established it. Black-box AI is a non-starter for industrial buyers.

4. Customer data isolation by default

Per-customer K8s namespace + per-customer encryption keys + per-customer S3 prefix. Cross-customer model training is federated only — raw data never leaves the customer boundary. SOC 2 + ISO 27001 + IEC 62443 in the pipeline.
