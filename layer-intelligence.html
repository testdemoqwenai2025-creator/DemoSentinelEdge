Graph RAG

Retrieval-augmented reasoning
graph-rag-traversal.json
{
  "query": "why did line 3 throughput drop Tuesday morning?",
  "evidence_chain": [
    {
      "node": "line3.compressorA.bearing1",
      "kind": "asset",
      "evidence": "vibration RMS elevated 2.1× baseline, 04:32 Tuesday",
      "source": { "sensor_id": "sen_vib_a3_line3", "ts": 1788561600 }
    },
    {
      "node": "line3.maintenance.log.2024.09.04",
      "kind": "maintenance_event",
      "evidence": "bearing1 flagged for replacement, parts ETA Friday"
    },
    {
      "node": "line3.erp.throughput",
      "kind": "kpi",
      "evidence": "throughput dropped 18% from 06:00 onward"
    }
  ],
  "answer": "Bearing 1 on Compressor A showed early-stage fault signatures at 04:32 Tuesday, causing the controller to derate the compressor for safety. Throughput dropped 18% as a direct consequence. Maintenance was scheduled for Friday; expect recovery by Monday.",
  "confidence": 0.91,
  "citations": ["sen_vib_a3_line3", "maint_log.2024.09.04", "erp_kpi.throughput"]
}

The graph is built incrementally as data flows in. Sensors become nodes. Assets (compressors, lines, fields) become parent nodes. Maintenance events and ERP records are linked via the asset they refer to. The graph has ~1M nodes for a typical mid-sized plant (200k sensors + 20k assets + 100k maintenance events + 700k ERP transactions).

Causal inference

Correlation is not causation.
Why this matters

Without causal inference, every anomaly looks the same and operators chase ghosts. With it, the system can recommend interventions — not just describe patterns. This is the moat: most industrial AI platforms stop at correlation. We are the first to ship causal at industrial scale.

Method

  • PC algorithm — builds a skeleton of conditional independence relationships over the sensor graph, then orients edges using v-structure detection
  • Do-calculus — answers "what if we intervened on variable X?" using the inferred causal graph
  • Validation — for every claimed causal edge, the platform runs a backtest against historical interventions (when operators actually did intervene on X) and reports the agreement rate

LLM-native query layer

Natural language in.

The query layer is what makes the platform usable for plant managers, ops VPs, and executives who don't want to learn a query language. Under the hood: a fine-tuned LLM that translates the natural-language question into (a) a TS-FM retrieval query, (b) a Graph RAG traversal, and (c) a causal-inference test. The final answer is composed from the three results, with citations back to the sensor readings, maintenance logs, and ERP records that grounded it.
