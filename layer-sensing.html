Sensor ontology

Turning bytes into meaning.

The sensor ontology is the contract between the physical world and the platform. It defines what a "measurement" is — physical quantity, unit, sample rate, uncertainty, location, lineage, calibration state — so any downstream layer can reason over it without bespoke integration.

Without this contract, every sensor is a snowflake. With it, a vibration reading from an SKF accelerometer on a Hailo-8 gateway in Plant A and a vibration reading from a Bosch MEMS on a Coral in Plant B are both first-class "vibration measurements" that the TS-FM can train on, the Graph RAG can reason over, and the LLM can cite.

Canonical schema

One canonical record, any sensor.

Every raw measurement is normalized to this canonical record at the edge gateway, before any inference runs. This is the contract every downstream layer relies on.

canonical-measurement.json
{
  "measurement_id": "meas_01H8X3F…",
  "sensor_id": "sen_press_a3_line3",
  "sensor_kind": "pressure",
  "physical_quantity": "compressor_outlet_pressure",
  "unit": "Pa",
  "value": 182450.0,
  "uncertainty": ±120.0,
  "timestamp_ns": 1788561600000000000,
  "sample_rate_hz": 1.0,
  "location": { "lat": 37.422, "lon": -122.084, "elevation_m": 12.0 },
  "lineage": {
    "ingest_protocol": "opcua",
    "source_node_id": "ns=2;s=Line3.CompressorA.OutletPressure",
    "ingest_ts": 1788561600005000000,
    "calibration_age_days": 42
  },
  "calibration_confidence": 0.97
}

The schema has six required fields (sensor_id, sensor_kind, physical_quantity, unit, value, timestamp_ns) and five optional fields that downstream layers use for reasoning (uncertainty, sample_rate_hz, location, lineage, calibration_confidence). Any field can be added without breaking downstream consumers — the schema is forward-compatible by design.

Self-calibration mesh

6.7% of manual recalibration cost, equivalent accuracy.

Every sensor drifts. Traditional approaches recalibrate via scheduled truck rolls (~$140 average per site visit). We use three mechanisms layered together:

1. Physics redundancy

When multiple sensors measure the same physical quantity (e.g., two pressure gauges upstream and downstream of a known obstruction), Bernoulli's equation constrains the relative drift. Any sensor that violates the physics constraint is flagged for recalibration.

2. Sparse ground truth

A small number of high-accuracy reference sensors (NIST-traceable) are deployed at <5% density. Their readings anchor the rest of the mesh. The cost is acceptable because we only need a few anchors per topology.

3. Distributed estimation

A graph neural network over the sensor topology infers per-sensor drift coefficients, updated hourly via federated learning across customer sites. No raw data crosses customer boundaries — only gradient updates.

Result

On a 10,000-node air quality mesh, this approach matches manual recalibration accuracy at 6.7% of the cost. Validated against the EPA AQS reference network in a 12-month trial.

Worked example — air quality mesh

A 10,000-node PM2.5 sensor deployment in a metropolitan area. Traditional approach: scheduled truck rolls every 90 days, $1.4M/year cost.
