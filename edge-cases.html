Sensors misbehave in 15 ways. Each must be detected and mitigated.
15 edge cases
1
Sensor dead
No data received
General mitigation: Heartbeat monitoring, last-seen tracking, store-and-forward diagnostics, auto-flag as 'silent failure'
Gas detector silent failure → 2oo3 redundancy with auto-flag. ESD valves have position feedback (no data = valve stuck = alarm).
ECG lead-off detected (impedance > 10K ohm). Patient-attached sensor silent = lead-off or sensor fault. Auto-alarm per IEC 60601-1-8.
LiDAR dead = critical failure → fail-safe pull-over within 10s. Camera dead = degrade to LiDAR-only perception. IMU dead = full stop.
Reactor thermocouple dead = critical. 3x redundant TCs + RTD. 2oo3 voting. Block ML inference if 2/3 dead.
PMU dead = critical for state estimation. 2x redundant PMUs per substation. Flag 'unobservable' if both dead.
Methane sensor dead = critical (silent failure) → 2oo3 redundancy. Auto-flag. Evacuate if 2/3 dead.
Chlorine residual sensor dead = critical (silent failure). 2x redundant + lab grab sample daily. Flag 'uncertain' if both dead.

Turbidity stuck at 0 NTU for > 30 min on running plant = sensor fault (impossible). Auto-flag. Boil-water advisory if confirmed.

Ingestion requirements (7)

Support millions of messages per day

Handle late data

Support replay for backfill and incident investigation

Schema enforcement
Confluent Schema Registry enforces Avro/Protobuf/JSON Schema on write. Backward/forward compatibility checked at deploy time.

Functional Design · Stream Processing Pipeline
For every telemetry message: 15 steps. Each step idempotent. Exactly-once via 2PC.
15 steps
1
Parse and validate schema
Avro/Protobuf parse → enforce Schema Registry. Reject malformed → dead-letter topic. Validate required fields + types.
2
Authenticate device and verify topic
mTLS cert validation. Topic ACL check (device can only publish to its own namespace). Rate-limit per device (100 msg/sec default).
3
Check timestamp sanity
1970 < ts < now+5min. Reject future timestamps. Flag clock-skew suspicion. Server receive time as fallback.
4
Convert to canonical unit
LLM-assisted unit normalization (psi → Pa, °F → °C). Per-device unit config cached in Redis. Physics sanity check post-conversion.
5
Enrich with asset metadata
Tag → Asset → System → Plant hierarchy lookup from PostgreSQL. Cache in Redis (5-min TTL). Adds: asset criticality, location, owner, regulatory class.
6
Apply quality rules
Range validation (e.g. bearing T < 200°C). Physics constraints (e.g. voltage 0-500kV). Quality flag (Good/Uncertain/Bad) per ISA-95.
7
Detect duplicates and gaps
Idempotency key (sensor_id + ts + value_hash). Dedup within 100ms window. Sequence gap detection on critical tags. Gap-fill via physics model.
8
Update sensor health state
Heartbeat monitoring (last-seen-ts). Stuck-value detection (zero variance > N hours). Drift tracking against reference. Calibration status (active/expired).
9
Update asset state and digital twin
Asset state (running/stopped/fault). Digital twin update (current setpoint, current load, current efficiency). State machine transitions logged.
10
Run deterministic safety rules
Independent of ML. Hardcoded thresholds per ISA-18.2 (e.g. methane > 2% → evacuate). Voting logic (2oo3 redundancy). SIS-grade reliability.
11
Run statistical anomaly detection
Z-score > 3σ on rolling window. EWMA control limits. CUSUM for slow drift. Median absolute deviation (MAD) robust statistics.
12
Run ML inference
TS-FM (350M params, zero-shot, 0.89 AUC-ROC). Liquid placement decides edge-vs-cloud. Model version from MLflow registry. Inference cached 5-min TTL.
13
Correlate with other alerts
Time-window correlation (alarms within 60s on same system). Causal inference (PC algorithm + do-calculus). Root-cause graph (Neo4j) identifies source.
14
Emit alerts, metrics, and events
Alert → MQTT broker + SCADA + pager. Metrics → Prometheus. Events → Kafka audit topic. Alarm priority per ISA-18.2 (high/med/low).
15
Persist raw and processed data
Raw → Kafka 7d + Iceberg (immutable). Processed → TimescaleDB hot 90d + ClickHouse OLAP. Audit → OpenSearch WORM index. All time-stamped + signed.

Functional Design · Rule Engine
9 rule types. Safety-critical rules independent of ML. Voting across sensors. Maintenance-mode aware.
9 rule types
1
Threshold rules
value > X → alert (e.g. methane > 1%). High/low/both. Per-asset configurable. Time-of-day aware (different thresholds day/night).
2
Rate-of-change rules
dT/dt > X → alert (e.g. reactor T rising > 5°C/min = runaway risk). Distinguishes slow drift from rapid change. Per-asset configurable.
3
Deadband rules
|value - last_value| > X → publish (saves bandwidth on slow-changing tags). Per-asset configurable. Combined with store-and-forward.
4
Duration rules
value > X for > T seconds → alert (e.g. bearing T > 90°C for > 5 min). Distinguishes transient from sustained. Per-asset configurable.
5
Multi-condition rules
value1 > X AND value2 < Y → alert (e.g. flow low + pressure high = blockage). Boolean AND/OR/NOT. Per-asset configurable. ISA-95 rule grammar.
6
Asset state rules
if asset.state == 'running' AND vibration > X → alert (e.g. vibration on stopped motor = sensor fault, not real). State machine from DCS/PLC.
7
Maintenance mode rules
if asset.in_maintenance → suppress alarms (with audit trail + 2-person approval). Time-limited (auto-restore 4h). CMMS sync required.
8
Voting rules from multiple sensors
if 2 of 3 methane sensors > 1% → evacuate (2oo3 voting). Per-asset-group configurable. Defeats single-sensor-fault false positive.
9
Safety-critical rules independent of ML
Hardcoded thresholds, never overridden by ML. Independent code path. SIL-2/3 certified (IEC 61511). Tested quarterly. Red-team exercises.
