Versioning

All schemas use com.aisensoredgecomp.v1 namespace. Breaking changes require a new namespace (v2). Backward-compatible changes (adding optional fields, adding enum values) can be made in-place. Schema Registry enforces BACKWARD compatibility.

ML design

TS-FM + RUL + model monitoring.

Three subsystems compose the ML layer:

1. TS-FM (foundation model)

350M-parameter causal transformer, pretrained on 50M hours of public industrial time-series (NASA bearings, Case Western Reserve, SECOM, UCI gas turbine, ARPA-E, UCR/UEA archive). Zero-shot AUC-ROC 0.89, beats Chronos-B1 baseline of 0.82.

Architecture: 24 layers, 1024 hidden, 16 attention heads, cross-attention for sensor fusion, causal-aware loss (PC algorithm validity test). PyTorch training pipeline with AMP + gradient accumulation, exports to ONNX for edge inference.

2. RUL predictor

Fine-tuned regression head on TS-FM backbone. Per asset class (compressor, pump, motor, etc.), takes last 7 days of multi-modal sensor readings, predicts rul_hours with confidence.

Per-asset-class fine-tuning via federated learning: each customer contributes gradients (with DP noise ε=1.0) without sharing raw data. Aggregated in Intel SGX secure enclave.

3. Model monitoring

Three monitors run continuously: feature drift (PSI > 0.2 triggers retraining), confidence distribution (output drift over time), ground-truth feedback (per-asset-class confusion matrix).

Prometheus metrics exposed. Alertmanager routes drift alarms to the ML team for review. Automated retraining pipeline + canary deployment of new models.
