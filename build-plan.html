Phase 1 — Foundation
Stand up the smallest end-to-end loop that delivers value: ingest → store → alert → dashboard
4–6 weeks
Dependencies: None — greenfield. Can run in parallel with hardware procurement + sensor commissioning.

Deliverables (6)

MQTT ingestion
EMQX broker (3-node cluster, MQTT 5.0 + Sparkplug B). mTLS auth. Per-device topic ACLs. Schema Registry (Avro). Target: 10K msgs/sec sustained, 100K/sec burst.
Device simulator
Python + asyncio. Generates synthetic telemetry for 100 sensors (vibration, temp, pressure, flow, gas). Configurable fault injection (stuck value, drift, spike, dead). 1M-row dataset for replay.
Telemetry validation
Avro schema enforcement. Per-field range checks (e.g. bearing T < 200°C). Physics sanity (e.g. pressure 0-5000 psi). Malformed → dead-letter topic. Violation rate alert > 1%.
Time-series storage
TimescaleDB (PostgreSQL + hypertables). 90-day hot retention. Continuous aggregates for hourly/daily rollups. Compression (8-12x via delta-of-delta).
Basic dashboards
Grafana with TimescaleDB data source. Sensor overview, asset list, alarm panel. Read-only role for operators. Mobile-responsive. Light/dark theme.
Simple threshold alerts
Per-sensor threshold (high/low). Alarm state machine (active/ack/cleared) per ISA-18.2. Email + PagerDuty routing. Audit log (ack/silence actions).

Engineering tasks (8)

  • Terraform: provision VPC, K8s cluster (3 nodes), EMQX, TimescaleDB, Grafana
  • Helm charts: emqx-cluster, timescaledb-cluster, grafana, schema-registry
  • Device simulator: Python package, configurable per-sensor profile, fault injection CLI
  • Avro schemas: sensor-reading.avsc, alarm-event.avsc, asset-state.avsc — versioned in Schema Registry
  • Alerting: Alertmanager + PagerDuty integration. Email/SMS/pager routes per severity
  • Dashboards: 3 Grafana dashboards (sensor overview, alarm panel, asset health). Templating per customer
  • CI/CD: GitHub Actions → build → push to container registry → ArgoCD sync
  • Documentation: 5-minute quickstart, 30-minute architecture walkthrough, API reference

Success criteria (7)

  • Ingest 10K msgs/sec sustained for 24h with < 1% message loss
  • Round-trip latency: sensor → dashboard < 2 sec (P95)
  • Schema violation rate < 1% (else: alert + investigate)
  • Threshold alert → operator notification < 5 sec (P95)
  • Dashboard query response < 500 ms (P95) at 1M rows
  • Successful restore from backup < 30 min
  • 0 high-severity security findings in code scan (Trivy + Semgrep)

Acceptance tests (6)

  • Load test: 100K msg/sec burst for 60 sec, no broker crash, all messages persisted
  • Fault injection: kill EMQX primary, failover < 10 sec, no message loss
  • Fault injection: kill TimescaleDB primary, Patroni failover < 10 sec, no data loss
  • Schema test: send malformed Avro → must land in dead-letter, alarm fired
  • Replay test: replay 1M-row dataset, all 1M rows persisted, 0 duplicates
  • Restore drill: restore from last nightly backup to isolated cluster, verify data integrity

Risks + mitigations (3)

EMQX performance tuning
Default config may not hit 10K/sec. Mitigation: tune Erlang async thread pool, socket buffer sizes; benchmark before production.
TimescaleDB compression timing
Compression jobs may lock inserts. Mitigation: run compression during low-traffic window; use TimescaleDB 2.14+ with concurrent compression.
Schema evolution
First schema is critical — wrong field types break everything downstream. Mitigation: design schema with a senior engineer + 2-day review; backward-compatible from day 1.

Phase 2 — Edge Resilience
The edge must survive network outages, equipment faults, and never lose data or fire false alarms
4 weeks
Dependencies: Phase 1 complete. Edge hardware selected (Hailo-8 + industrial gateway). At least 1 design-partner site available for field testing.

Deliverables (5)

Store-and-forward
Edge SQLite circular buffer (250 GB capacity, ~72h at design-partner sensor volume). Replay on WAN restore with idempotency. Priority lanes: alarms > safety > telemetry. Replay rate-limited to avoid cloud overload.
Offline buffering
Buffer survives edge gateway crash + reboot. WAL mode SQLite (atomic, ACID). Power-loss protection via UPS (8-hour holdover) + SSD PLP (Power Loss Protection). Buffer status telemetry to cloud.
Duplicate detection
Idempotency key: sensor_id + ts (1s bucket) + value_hash. Dedup within 100 ms window at ingest. Redis-backed bloom filter for fast lookup. Drops logged with sample for diagnosis.
Sequence gap detection
Per-device sequence number tracking. Gap > N sec on critical tags → retransmission request. Gap-fill via physics model (e.g. linear interpolation for slow-changing tags). Gap log for compliance.
Edge rule engine
Lua + WASM rule engine. Threshold, rate-of-change, deadband, duration, multi-condition rules. Per-asset configurable. Maintenance-mode aware. 2oo3 voting. Local alerting (never round-trips to cloud for safety-critical).

Engineering tasks (10)

  • Edge runtime: Rust service (ingest loop, rule engine, store-forward, scheduler). Cross-compile for x86_64 + ARM64
  • SQLite schema: 3 tables (readings, alarms, audit_log). WAL mode. Daily vacuum cron
  • Idempotency: Redis on edge (single-node, persistence AOF). Bloom filter (10M keys, 0.1% FPR)
  • Sequence tracking: per-device state in Redis. Gap detection at ingest (Flink job in cloud + edge local)
  • Rule engine: Lua sandbox + WASM runtime (Wasmtime). Rule DSL: declarative YAML, compiled to Lua
  • Rule types: threshold, rate-of-change, deadband, duration, multi-condition, asset-state, maintenance-mode, voting (2oo3)
  • Local alerting: MQTT local broker (mosquitto) on edge → SCADA + pager gateway. Hardwired alarm outputs for SIL-3
  • Edge ↔ cloud sync: differential replay (only send what cloud missed). Bandwidth-aware (compressed + prioritized)
  • UPS + SSD PLP: hardware spec + procurement. UPS status telemetry (battery %, runtime estimate, on-battery event)
  • Field test plan: deploy at 1 design-partner site, simulate WAN outage (pull cable), validate 72h buffer + replay

Success criteria (7)

  • Edge survives 72h WAN outage with zero data loss (verified by replay)
  • Edge rule engine fires local alarm < 200 ms (P95) from sensor reading
  • Duplicate detection: < 0.01% duplicate rate at 100K msg/sec ingest
  • Sequence gap detection: catches 100% of gaps > 5 sec on critical tags
  • Store-and-forward replay: full buffer (250 GB) replays to cloud < 4h on WAN restore
  • Edge gateway crash + reboot: 0 data loss, 0 alarm missed, < 30 sec downtime
  • UPS switchover (power loss): 0 data loss, 0 alarm missed, < 100 ms downtime

Acceptance tests (6)

  • WAN outage test: pull WAN cable for 72h, verify buffer fills, no data loss. Restore WAN, verify replay completes
  • Power loss test: kill power to edge gateway. UPS holds. Verify 0 data loss. Verify edge reboot + catch-up
  • Fault injection: stuck value (set sensor to constant 50 for 1h) → must alarm at 1h variance=0
  • Fault injection: duplicate (replay same msg 10x) → 9 must be dropped, 1 persisted
  • Fault injection: gap (skip seq #50-#60) → gap alarm fires, retransmission request sent
  • Field test at design partner: 7-day deployment, daily WAN outage test, daily restore drill

Risks + mitigations (4)

Edge hardware selection delay
Some industrial gateways have 12+ week lead times. Mitigation: order 2 alternatives in parallel; use dev kit while waiting for production.
Field test access
Design partner may not allow 'pull the WAN cable' test. Mitigation: simulate at our lab with real device + network emulator; schedule field test week 4.
SQLite write amplification
250 GB buffer on consumer SSD = 30-60 days of life. Mitigation: use industrial SSD (MLC NAND, 5-year warranty); monitor SSD wear via SMART.
Rule engine performance
Lua + WASM may not hit 1 ms SLA on $1 MCUs. Mitigation: target x86 + Hailo-8 (minimum), drop to TinyML only when required.

Phase 3 — Advanced Stream Processing
Real-time stream processing with Kafka + Flink. Watermarks, late data, asset enrichment, alert correlation.
6 weeks
Dependencies: Phase 1 + Phase 2 complete. Phase 2's edge buffer feeds the cloud pipeline. At least 1 design partner with > 1K sensors for scale testing.

Deliverables (5)

Kafka/Flink pipeline
Kafka 5 brokers (KRaft mode, no Zookeeper), 3 topics (raw, processed, audit). Flink 8 TMs (4 vCPU + 8GB each), exactly-once via 2PC. Checkpoint every 30s to S3. Savepoint for upgrades.
Watermarks
Flink watermark strategy: bounded out-of-orderness (5 min for satellite, 30 sec for fiber). Punctuated watermarks for explicit event-time markers. Late events → side-output (not dropped).
Late data handling
Side-output for late events (> watermark). Allowed lateness 10 min (configurable). Update state on late arrival. Late events re-trigger alarm if state changes. Audit log for late arrivals.
Asset enrichment
Asset metadata (hierarchy, criticality, owner, regulatory class) lookup from PostgreSQL at ingest. Cache in Redis (5-min TTL). Enrichment adds 8 fields per message. Joins: sensor → asset → system → plant.
Alert correlation
Time-window correlation (alarms within 60 sec on same system → cluster). Root-cause graph (Neo4j) identifies source alarm. Cascading alarm suppression (display root cause, not 50 derived alarms). Causal inference (PC algorithm) for related alarms.

Engineering tasks (13)

  • Kafka cluster: 5 brokers, KRaft mode, RF=3, min.insync.replicas=2. Tiered storage to S3 (offload cold segments)
  • Flink cluster: 8 TMs, RocksDB state backend, async checkpointing to S3. Savepoint + restore tested weekly
  • Flink jobs: 6 jobs (ingest-validate, enrich, quality-rules, anomaly-detect-pre, alert-correlate, persist)
  • Watermark strategy: per-source configurable (satellite 5 min, fiber 30 sec, 5G 10 sec). Side-output sink for late
  • Late data: Flink allowed lateness 10 min. Update state + re-fire alarm if needed. Audit log for late arrivals
  • Asset enrichment: PostgreSQL 'assets' table (1M rows max). Redis cache (5-min TTL). Bulk-load on startup
  • Alert correlation: sliding 60-sec window, group by system_id, cluster by cause-and-effect graph (Neo4j)
  • Neo4j: cause-and-effect model (asset → triggers → alarm). Loaded from CMMS + DCS P&ID. Updated on new asset registration
  • Causal inference: PC algorithm (causal-learn Python lib). Run nightly on alarm history. Updates cause-and-effect graph
  • Cascading suppression: if root cause alarm fires, suppress derived alarms for same system for 5 min
  • Backpressure: Kafka quotas per topic, Flink HPA on lag, Circuit Breaker to shed load if persistent
  • Schema evolution: Confluent Schema Registry, backward + forward compatible. Dual-publish during migration
  • Monitoring: Flink metrics → Prometheus. Lag alert at > 10K msg. Savepoint success/failure alert

Success criteria (7)

  • Pipeline ingests 100K msg/sec sustained with < 5 sec end-to-end latency (sensor → alarm)
  • Watermark strategy: 99.9% of events processed within 30 sec of arrival
  • Late events: < 0.1% of total. Late events handled correctly (state updated, audit logged)
  • Alert correlation: 90% of cascading alarms correctly suppressed (display root cause only)
  • Causal inference: correctly identifies root cause in 80% of historical incidents (backtested)
  • Savepoint + restore: full pipeline restarts from savepoint < 5 min with zero data loss
  • Backpressure: Kafka lag stable (< 10K msg) at 100K msg/sec ingest for 24h

Acceptance tests (7)

  • Load test: 100K msg/sec for 24h. Verify no data loss, no duplicate, end-to-end latency < 5 sec
  • Late data: inject 1000 events with 10-min late timestamp. All must hit side-output, state updated correctly
  • Alarm storm: inject 50 simultaneous alarms on one system. Root-cause correctly identified, 49 derived suppressed
  • Causal inference: backtest on 90 days of historical alarms. Verify cause-and-effect graph updates correctly
  • Savepoint: trigger savepoint, restart Flink job. Verify zero data loss, savepoint < 5 min
  • Backpressure: 200K msg/sec for 10 min (overload). Verify Circuit Breaker engages, Kafka lag stabilizes, no crash
  • Schema evolution: deploy new Avro schema (add field with default). Verify zero ingestion disruption

Risks + mitigations (4)

Flink state growth
RocksDB state can grow to TBs. Mitigation: incremental checkpointing, state TTL (90 days), periodic compaction.
Neo4j scale
Cause-and-effect graph for 1M assets = ~10M relationships. Mitigation: Neo4j 5.x with sharding, or move to PostgreSQL + Apache AGE if scale issues.
Watermark tuning
Wrong watermark = either drop too many events or accept stale data. Mitigation: per-source tuning, weekly review of late-arrival rate, alert if > 1%.
Causal inference accuracy
PC algorithm may produce wrong causal links from noisy data. Mitigation: human-in-the-loop review of high-confidence causal links; conservative threshold for new links.

Phase 4 — ML and Digital Twin
TS-FM anomaly detection, predictive maintenance, digital twin state, root-cause graph
8–12 weeks
Dependencies: Phase 3 complete. At least 6 months of historical data at design partner. Labeled maintenance records from CMMS. GPU cluster (8× A100 80GB) for TS-FM training.

Deliverables (4)

Anomaly detection
350M-param TS-FM (transformer + sparse autoencoder). Pretrained on 50M hours of public industrial data (NASA bearings, CWRU, SECOM, ARPA-E). Zero-shot on any asset class. 0.89 AUC-ROC. Fine-tunable per asset class with 7 days of data.
Predictive maintenance models
Per-asset-class RUL (Remaining Useful Life). XGBoost + TS-FM features. Trained on labeled maintenance events from CMMS. Output: probability of failure in 7/14/30 days + recommended action.
Digital twin state
Asset state machine (running/stopped/maintenance/fault). Digital twin update on every state change. Current setpoint, current load, current efficiency. Persisted in PostgreSQL + Neo4j. Time-travel query (Iceberg snapshot).
Root-cause graph
Neo4j cause-and-effect graph (sensor → asset → system → plant). Causal inference (PC algorithm + do-calculus). When alarm fires, query graph for upstream causes (within 60-sec window). Display root cause + recommended action.

Engineering tasks (12)

  • TS-FM training: 8× A100 80GB cluster. PyTorch + FSDP. Mixed precision (bf16). 50M hours pretraining, 2 weeks wall clock
  • TS-FM inference: ONNX Runtime (x86) + Hailo Model Compiler (Hailo-8). Liquid placement decides edge-vs-cloud. Inference cache 5-min TTL
  • RUL models: per-asset-class XGBoost. Features from TS-FM (embeddings) + hand-crafted (rolling stats, trends). Train on CMMS labeled events
  • Model registry: MLflow. Model versioning, stage transitions (staging/prod). Canary deploy (5% traffic first)
  • Drift detection: Evidently AI. PSI > 0.2 → retrain trigger. Weekly drift report to ML team
  • Federated learning: DP noise + SGX secure aggregation. Cross-customer model improvement. Opt-in per customer. Gradients only, no raw data leaves customer
  • Digital twin: PostgreSQL 'asset_state' table (time-series). Neo4j 'cause_effect' graph. Asset state machine (UML state diagram → JSON config)
  • Root-cause query: Cypher query on alarm → upstream sensors + recent state changes + causal links. Cached 5-min TTL
  • LLM-native query: Graph RAG (LangChain + Neo4j + OpenAI/Anthropic). Operator asks 'why did this alarm fire?', gets cited answer with sensor trace
  • Model monitoring: PSI, KS-test, ground-truth feedback loop (operator marks alarm false → retrain signal). Prometheus metrics for inference latency, accuracy drift
  • MLOps: MLflow + Feast (feature store) + Evidently (drift). CI/CD for models (retrain → test → canary → promote). Airflow DAGs
  • Documentation: model cards per asset class. Evaluation reports. Bias + fairness checks (esp. for hospital/AV)

Success criteria (8)

  • TS-FM zero-shot: 0.89 AUC-ROC on unseen asset classes (backtested on 90 days holdout)
  • RUL prediction: < 20% MAPE on assets with > 100 historical failures (backtested)
  • False positive rate: < 5% at 95% recall (target; vs 28% threshold rules)
  • False negative rate: < 1% (safety-critical — must catch all real danger)
  • Digital twin: 100% of asset state changes captured < 5 sec latency
  • Root-cause query: < 2 sec (P95) for causal-graph lookup
  • LLM-native query: < 5 sec (P95) for Graph RAG answer with citations
  • Federated learning: 0 raw data leaves customer. Only DP-noised gradients shared

Acceptance tests (9)

  • Zero-shot test: deploy TS-FM on unseen asset class (e.g. train on pumps, test on compressors). Verify AUC > 0.85
  • RUL backtest: 90 days historical data. Predict failures 7 days ahead. Verify MAPE < 20%
  • False positive: 30-day field test at design partner. Verify < 5% FP rate (vs 28% threshold baseline)
  • False negative: red-team with simulated failures (e.g. bearing fault injected). Verify 100% detection
  • Digital twin: state change → query digital twin within 5 sec. Verify accurate state
  • Root cause: trigger known cascade (e.g. power loss → 50 alarms). Verify root cause identified correctly
  • LLM query: operator asks 'why did alarm X fire?'. Verify cited answer with sensor trace + recommended action
  • Federated learning: train across 2 design partners. Verify model improves for both. Verify 0 raw data shared
  • Drift: induce distribution shift (e.g. new asset class). Verify PSI > 0.2 triggers retrain alert

Risks + mitigations (5)

TS-FM training cost
8× A100 for 2 weeks = $50-80K. Mitigation: preemptive GPUs (60% discount), spot instances, AWS/Google Cloud credits for startups.
Labeled data scarcity
CMMS labels often wrong or incomplete. Mitigation: human-in-the-loop labeling, active learning on uncertain labels, use TS-FM zero-shot as fallback.
Federated learning complexity
DP + SGX is research-grade. Mitigation: ship non-federated first (Phase 4), add federated in Phase 5 hardening.
LLM hallucination
LLM may invent causes. Mitigation: Graph RAG (grounded in graph data), citation chain, operator can verify each claim against sensor trace.
Causal inference false positives
PC algorithm may produce spurious causal links. Mitigation: human-in-the-loop review, conservative threshold, only display high-confidence links to operator.

Phase 5 — Hardening
Production-grade security, chaos testing, failover drills, audit logs, compliance reports, operator UX validation
6+ weeks
Dependencies: Phase 1-4 complete. At least 3 design partners in production. Compliance officer engaged. Security partner (Bishop Fox or similar) for penetration test.

Deliverables (6)

Security hardening
SOC 2 Type II audit prep. IEC 62443-3-3 SL-3 scoping. Penetration test (3rd party). mTLS enforced everywhere. Secrets in HashiCorp Vault. Network segmentation per asset class. Secure boot + TPM 2.0 on edge. SAST + DAST + SCA in CI/CD.
Chaos tests
Chaos engineering framework (Litmus or Gremlin). Inject: node kill, network partition, disk full, clock skew, broker crash, Flink job kill, DB failover. Run weekly. Production + staging. Auto-rollback on SLO breach.
Failover tests
Periodic failover drills: EMQX cluster failover (weekly), TimescaleDB Patroni failover (weekly), Kafka broker failover (monthly), region failover (quarterly), edge WAN loss (daily at design partner). Documented runbook + automated test.
Audit logs
Append-only event log (OpenSearch with WORM index). Every operator action (acknowledge, bypass, override, login) creates timestamped + signed event. Retention 5-10 years per regulatory. Tamper-evident (chain of hashes).
Compliance reports
Auto-generated audit-ready reports: EPA OOOO-b (methane emissions, monthly), BSEE SEMS (offshore safety, annual), OSHA PSM (chemical safety, quarterly), NERC CIP (grid cybersecurity, quarterly), HIPAA (hospital, annual), FDA 510(k) (device, annual). Regulator format (CEDRI XML, CSV, PDF).
Operator UX validation
Shadow sessions with real operators (10+ per design partner). UX testing (System Usability Scale target > 80). Alarm rationalization per ISA-18.2 (target < 10 alarms/operator/shift). Drill mode for new operators. Bilingual support (EN/ES for offshore US GoM).

Engineering tasks (14)

  • SOC 2 Type II: 12-month observation period. Engage Vanta/Drata for evidence collection. Annual audit by 3rd party (BDO, KPMG, or similar)
  • IEC 62443-3-3 SL-3: scoping + gap analysis. Engage TÜV Rheinland or DNV for assessment. Zonal + conduit model. SL 3 requires: identification, use control, system integrity, data confidentiality, restricted data flow, timely events, resource availability
  • Pen test: Bishop Fox or NCC Group. Black-box + white-box. Findings → fix → re-test. Annual cadence
  • Secrets management: HashiCorp Vault (open-source). Per-tenant secrets. Auto-rotation 90 days. Edge: Vault Agent + AppRole auth
  • Network segmentation: K8s NetworkPolicy per namespace. Edge VLAN per asset class. mTLS via cert-manager + custom CA. Zero-trust
  • Secure boot: UEFI Secure Boot + signed boot chain. TPM 2.0 for key storage + measured boot. Remote attestation
  • SAST + DAST + SCA: SonarQube (SAST), OWASP ZAP (DAST), Trivy + Snyk (SCA). In CI/CD, block on high
  • Chaos: Litmus or Gremlin. Weekly chaos day. Game days with operations team. Auto-rollback if SLO breach
  • Failover drills: automated via Argo Workflows. Documented runbooks. Quarterly DR exercise with ops team
  • Audit log: OpenSearch with WORM index (immutable). Per-action hash chain. Tamper-evident verification tool
  • Compliance reports: Airflow DAGs. Monthly EPA, quarterly OSHA/NERC, annual HIPAA/FDA. Regulator format (XML/CSV/PDF). Auto-send to compliance officer for review
  • Operator UX: shadow sessions (10+ per partner), SUS survey, alarm rationalization workshop, drill-mode UI feature
  • Bilingual: i18n with ICU MessageFormat. EN + ES (offshore GoM). Add ZH/AR per design partner region
  • Documentation: security whitepaper, compliance matrix, incident response runbook, operator training videos

Success criteria (8)

  • SOC 2 Type II: 0 material findings. Audit complete. Report available to customers
  • IEC 62443-3-3 SL-3: 0 gaps. Certification by TÜV/DNV
  • Pen test: 0 critical/high findings after remediation. Annual cadence established
  • Chaos tests: 100% of chaos experiments auto-recover within SLO. Mean time to detect < 1 min, mean time to recover < 5 min
  • Failover drills: 100% pass rate. RPO 5 min, RTO 30 min for hot path
  • Audit log: 100% of operator actions logged. Tamper-evident verification passes
  • Compliance reports: 100% on-time generation. 0 errors in regulator format
  • Operator UX: SUS > 80 (industry standard for 'good'). Alarm rate < 10/operator/shift

Acceptance tests (10)

  • SOC 2 audit: 12-month observation, 0 material findings
  • IEC 62443: third-party assessment, 0 SL-3 gaps
  • Pen test: 3rd party, 0 critical/high after fix
  • Chaos day: inject 10 chaos experiments (node kill, network partition, disk full, clock skew, broker crash, Flink kill, DB failover, region failover, edge WAN loss, S3 outage). All auto-recover within SLO
  • Failover drill: kill EMQX primary in production, verify failover < 10 sec, 0 data loss
  • Audit log: query for all operator actions on a specific alarm. Verify all logged + signed + tamper-evident
  • Compliance report: generate EPA OOOO-b monthly report. Verify XML format, all required fields, sensor lineage for every data point
  • Operator UX: shadow 10 operators, run SUS survey. Target > 80. Run alarm rationalization workshop, target < 10 alarms/shift
  • Bilingual: switch UI to ES, verify all alarms localized
  • DR drill: full restore from backup to isolated cluster. RPO 5 min, RTO 30 min

Risks + mitigations (5)

SOC 2 audit timeline
12-month observation means we can't ship SOC 2 report until 12 months after Phase 5 start. Mitigation: start SOC 2 observation immediately; provide SOC 2 Type I in interim.
IEC 62443 complexity
SL-3 certification is non-trivial. May take 18-24 months. Mitigation: scope to specific deployment (e.g. chemical plant only) for first certification; expand later.
Operator adoption
Operators may distrust ML alarms. Mitigation: Phase 5 includes shadow mode (ML suggests, operator decides) for 30 days, then advisory mode, then full trust. Feedback loop for false alarms.
Compliance drift
Regulations change. Mitigation: compliance officer on retainer, quarterly regulatory review, automated report format updates.
Bilingual content drift
Translations can become stale as features change. Mitigation: i18n linter in CI/CD, native-speaker review per major release.
